01

Overview

A 286 machine around a 286 core

PCAT-286 is the machine that SPK286, a synthesizable 80286, plugs into: the AT bus bridge, memory, chipset, storage, audio and EGA video that turn the CPU into something a PC/AT BIOS can boot. The repository builds one profile, PCAT-286, for the ZXTRES+.

286

A real 80286 core

SPK286 runs real and protected mode with a six-byte prefetch queue and 24-bit physical addressing. Eight CPU speed profiles can be switched from the OSD without a reboot.

AT

The AT chipset

Two PICs, two DMA controllers, PIT, 8042 keyboard controller with A20 and CPU reset, RTC/CMOS, plus floppy, IDE, serial mouse, joystick and Sound Blaster, OPL2, C/MS, Tandy and MPU-401 audio.

EGA

EGA, with a VGA extension

EGA is the boot video device. A bounded VGA 13h+ extension adds mode 13h, unchained modes and a DAC, with Native, 15 kHz CRT and converted output.

How to read this report

BIOS/DOS, Windows 3.1, OS/2 and games have been observed on the ZXTRES+ (zxtres/README.md lists the evidence level of each feature). These are observations: they do not imply complete chipset, protected-mode corner-case or historical timing certification. Section 10 lists what is still open.

02

Logical design

Machine architecture

SPK286 owns instructions, architectural state, segmentation, protection, exceptions, prefetch and the bus interface unit. The motherboard owns everything around it: A20 gating, address decode, arbitration and the side effects of every peripheral.

Logical view of the production machine. The device router and the top level are the authoritative decode; this figure shows ownership, not every signal.

Bus bridge contract

  • The bridge retains a request's address, cycle class, direction, byte lanes and payload until it completes, once, even across READY stalls, reset cancellation and repeated identical requests.
  • Aligned RAM words use the x16 RAM path; EGA and byte devices keep individual accesses and their side effects. The CPU already splits odd words.
  • A0 and active-low BHE select the low and high byte lanes.
  • READY, LOCK and HOLD/HLDA remain functional dependencies in every speed profile.
  • PIC vectors come from the second of two accepted INTA transfers.
  • DMA, refresh and ROM loading share explicit arbitration. Loader writes while the CPU is held in reset need no grant from a running CPU.

Reset, A20 and clocks

  • The first fetch is the native 286 reset vector FFFFF0h, served by the high BIOS alias.
  • The 8042 controls A20 and CPU reset; CPU SHUTDOWN also requests the AT reset path used by BIOS protected-mode return services.
  • A20 masking exempts the high BIOS alias, so reset fetches stay valid with A20 off.
  • Code and data read buffers and a single-entry posted-write buffer cut memory overhead while keeping write ordering, snooping and reset/drain rules.
  • PIT channel 1 supplies the emulated AT refresh request; physical SDRAM refresh is also kept by its controller.
  • Production debug mutation inputs of the CPU wrapper are disabled.

Memory map and RAM backing

Addresses are CPU-visible, before translation to the private backing RAM. Unmapped reads return FFh per byte and unmapped writes have no effect. ROM writes are blocked while the CPU executes.

UMB and EMS

  • EMS provides 128 pages of 16 KiB (2 MiB), selected through ports 260h-263h.
  • Writing 00h-7Fh maps and enables a window, FFh disables it and 80h-FEh keeps the previous mapping. Windows start disabled after reset.
  • UMB and EMS have no OSD enable switch. DOS needs a compatible memory manager to expose them.
  • EMS backing lives at backing-RAM 200000h-3FFFFFh; CPU RAM at and above 2 MiB is translated up by 2 MiB to avoid aliasing it.
  • The CPU BIOS alias is resolved before the backend boundary and is never reapplied inside the read buffers or the RAM owner.

Board SDRAM

The AT RAM sits in the ZXTRES+'s 64 MiB SDRAM, behind the read buffers and the posted-write buffer, so the machine above the owner does not depend on the memory behind it. spk286_at_mister_sdram_owner serves every CPU, DMA and loader access.

Audio

  • Sound Blaster, OPL2, C/MS, Tandy and MIDI are enabled in config.tcl.
  • C/MS and Sound Blaster overlap at 220h; Audio 220h selects one of them or neither. OPL2 and Tandy have independent controls.
  • Tandy SN76489 writes use C0h-CFh when enabled, which takes that range away from DMA2. Leave Tandy off when software needs the whole secondary-DMA block.
  • MPU-401 is UART mode; an MT32-pi synthesizer is external hardware connected through USER I/O.
  • For Sound Blaster at its default IRQ use SET BLASTER=A220 I5 D1 T4 (I7 for IRQ7). It describes the OSD-selected hardware and does not enable it.

Input, storage and time

  • The controller keyboard path rebuilds AT make/break and extended sequences, including Print Screen, Pause and 101-key navigation, follows the 8042 translation setting and queues events while the output buffer is busy.
  • The PS/2 mouse appears as a serial mouse on COM1.
  • Floppy images: IMG, IMA and VFD. IDE images: VHD.
  • RTC time and CMOS snapshots pass through the host management window F400h-F47Fh, separate from CPU I/O 70h/71h.
  • Minimal DOS examples are CONFIG.SYS and AUTOEXEC.BAT in hdd/.
05

Graphics

EGA video and the VGA 13h+ extension

EGA is the boot video device: sequencer, graphics controller, attribute controller, four-plane VRAM and a UM6845R-based CRTC. CGA-compatible software uses EGA's compatible modes. There is no separate selectable CGA, Hercules, MDA or Tandy adapter.

Monitor and dot clock

  • Hardware → Monitor selects the EGA switch-sense profile: 5154/ECD (default), 5153/CGA for 200-line modes and 8×8 text, or 5151/MDA for monochrome mode 7/0Fh.
  • Apply changes with a reset so the EGA BIOS can read them during POST.
  • The dot clock follows Miscellaneous Output bit 2: about 14.318181 MHz for 200-line modes and 16.257 MHz for 350-line/MDA modes.
  • 200-line modes give about 15.7 kHz video; native 350-line and MDA timings are about 21.8 and 18.4 kHz.

350-line CRT output

The conversions store complete frames in the board SRAM and do not change the CRTC, display-enable or retrace state the guest sees. CRT offsets centre television output without moving native 350-line video; 25% / 50% scanline effects darken lines and do not change scan frequency.

i
31 kHz displays

The default 350-line CRT output is 480p 31 kHz (720×480 at 59.94 Hz), which a VGA monitor accepts; Native leaves the original rate for monitors that take it. VGA 13h+ Native already supplies its own raster of about 31.4 kHz; ordinary native EGA modes do not, so the board doubles the 200-line modes unless the scandoubler is off for a 15 kHz TV.

Optional VGA 13h+

Run VGATSR.COM in DOS to activate the extension and its INT 10h services (source: SW/vga/vgatsr.asm). The TSR checks AT286CTL before advertising VGA, supplies VGA detection and DAC BIOS calls, chains other calls to the loaded EGA BIOS and preserves and restores the EGA CRTC and attribute state around supported VGA modes.

Output rates

The VGA 13h+ CRT setting selects Native or television output.

  • Native: 912 clocks per line at 28.636 MHz (about 31.4 kHz).
  • 449 lines at about 70 Hz for 200/350-line profiles; 525 lines at about 60 Hz for 240-line, Dyna Blaster and 640-pixel planar profiles.
  • TV: 15.7 kHz at about 60 Hz.
  • Dyna Blaster starts through 12h and selects 256×232 only after its unchained register signature is complete.

What the renderers honour

  • CRTC Start Address, Offset 40-45, horizontal pel panning, one Line Compare split and Maximum Scan Line 0-7 in the unchained profiles.
  • Offset 32/64 for Dyna Blaster, 20-23 for planar 0Dh, 40-47 for the 640-pixel planar renderer. Scan Doubling.
  • CRTC timing registers 00h-09h are readable for read/modify/write software.
  • Attribute P5/P4 selection; Color Select bits 3:2 are not carried into DAC index bits 7:6.
  • While enabled, written DAC entries also affect EGA modes; untouched entries fall back to the EGA palette.
Out of scope, and the Pinball Fantasies case

Arbitrary Mode X resolutions, a programmable VGA CRTC, multiple splits, vertical panning, VGA text and other high-resolution modes and cycle-exact raster tricks are outside the extension. To keep EGA-only device detection, omit the TSR. A reset disables the extension, as does an IBM-compatible warm-boot write of 1234h to 0040:0072; run the TSR again afterwards.

Pinball Fantasies uses 320×240 for its normal table, 320×350 for its high table and 640×480/640×240 planar graphics for the intro and menu. Native shows every source row. TV keeps the normal table and the 640×240 rows but samples every second row of 320×350 and 640×480, so the high table's single-scanline score panel can disappear. Keep the VGA output setting fixed while a table runs, because the game calibrates its PIT raster when it loads. The high table is a 70 Hz mode, so a monitor must accept the 70 Hz signal to show it at its native rate; TV 60Hz outputs 60 Hz.

First boot

Firmware, boot splash and pause

The core ships without any BIOS. It holds the CPU in reset until both required ROMs are loaded from the OSD, shows a notice that names the missing one, and then releases the machine.

The two ROMs

  • PCAT BIOS: a 64 KiB image loaded at F0000h with the reset entry at offset FFF0h. BIOSes shipped as even/odd chips are interleaved into CPU order. Tested: PhoenixBIOS A286 1.01 and MR BIOS V1.65.
  • EGA BIOS: starts at C0000h and must fit in 32 KiB. An oversized image is rejected instead of overwriting UMB RAM.
  • The system BIOS invokes the EGA option ROM to initialize the video registers during POST.
  • There is no disk option-ROM slot: the AT BIOS must support the standard AT IDE interface at 1F0h/3F6h.

BIOS Builder

No ROM is distributed. The BIOS Builder prepares both from reference downloads, entirely in the browser: ega_bios.rom (the 16 KiB IBM 6277356 EGA ROM in CPU address order) and a 64 KiB PhoenixBIOS or MR BIOS image.

  • Every source and output is checked with SHA-256 against the images tested with the core.
  • Nothing is uploaded; a manual file picker replaces the automatic download if it is blocked.

The boot splash

A 320×200, 256-colour picture drawn by the VGA mode 13h raster, at the Native or 15 kHz rate the OSD selects. Its pixels are preloaded into the packed mode 13h framebuffer and its colours sit in a small palette table, so it needs no ROM of its own and never touches the emulated DAC.

  • It fades in over about half a second and out during its last second; F12 holds it at full brightness.
  • A sticky flag records the first CPU write to the framebuffer, so a BIOS reloaded from the OSD later shows black instead of what a program left there.
  • The flag is cleared with the video output reset, not left to a power-up value, and is kept from synthesizing to a constant.
  • Edit SW/splash_vga_320x200.png (indexed) and run SW/make_vga_splash_rom.py or its .ps1 twin to regenerate the pixel and palette images.
  • The splash is controlled by SPK286_AT_BOOT_SPLASH; commenting it out removes the artwork and its OSD option.

F12 pause and credits

  • F12 pauses the machine and scrolls the credits over the dimmed picture; F12 again resumes.
  • The CPU is put on HOLD: it finishes its bus cycle, raises HLDA and stays off the bus while devices keep running. Audio is muted.
  • The key never reaches the AT keyboard, and other key presses are ignored while paused.
  • F12 on the boot splash holds it, and the CPU, with the credits shown.
  • The OSD opens with Win + F12.
  • The credits text is credits/msg, converted with msg2hex into rtl/common/msg.bin.

Performance

CPU speed and runtime controls

CPU Speed in the OSD selects MAX, 6, 8, 10, 12.5, 16, 20 or 25 MHz. A pending change drains the current instruction and the outstanding bus work before the new profile applies, without a reboot.

MAX

Dependency-driven execution: instructions retire as soon as their real dependencies allow.

Available

6 to 25 MHz profiles

A provisional instruction-interval and logical-bus timing policy at the unchanged 50 MHz fabric clock. The nominal MHz labels do not certify native 286 pin timing, internal overlap or every instruction's historical duration.

Provisional

AT286CTL: per-program overrides

The DOS utility AT286CTL controls audio, joystick, MIDI and CRT offsets for individual programs through ports 8980h-898Fh. Each invocation replaces the ordinary override set; zero defers to the OSD for configurable fields, except VGA activation, and reset returns the controls to their defaults and disables the VGA extension. 

AT286CTL sb sbirq=5 adlib joy1=digital
GAME.EXE
AT286CTL reset

Runtime overrides cannot enable hardware omitted at build time. Installed RAM and the EGA monitor stay reset-applied OSD settings. The legacy 4.77, 7.16, 9.54, max, fake286 and nofake286 spellings are still accepted for register compatibility but do not select the SPK286 CPU speed.

DOS measurement tools

CHECKNUM runs the original CheckIt Dhrystone/Whetstone routines with a numeric frontend, keeping their BIOS-tick timer and software floating-point path. It prints Dhrystones per second and thousands of Whetstones per second. Its builder enforces the exact input hashes of the separately supplied CheckIt 3.03C files. The result keeps the original tick quantization and is not an inferred CPU frequency.

T286REF runs fixed register, branch and aligned-memory kernels, seven baseline and seven gross samples per case with 256 iterations each, and the host validates the returned CSV. It needs 8254 count/status read-back in binary mode 2 or 3, does not reprogram the PIT and keeps NOT_CALIBRATED in its output, because a latched count cannot reveal the reload divisor or the PIT crystal. It measures aggregate work, not native CPU pins, exact cycles or IRQ latency.

10

Known limitations

What still needs evidence

Repository cleanup does not resolve these limits, and none of them is a new full regression. Where a behaviour is unsettled, it is recorded as open instead of being picked quietly.

Chipset fidelity

  • Final DMA address/count update at terminal count and demand/single/block request lifetime.
  • DMA2 cascade and priority.
  • RTC SET clearing UIE and observable UIP/update timing.
  • PIC special-mask handling and speaker behaviour with GATE2 low.
  • PIT mode edges, BCD and read-back; RTC divider reset and DSE; PIC SFNM, EOI and spurious cascade; DMA external EOP; some 8042 commands and board straps.
  • Composed Sound Blaster playback needs backend-read accounting across memory, DMA and SB.

CPU protection and timing

  • LOCK privilege and zero-count REP precedence; LAR/LSL/VERR/VERW presence and conforming-code rules; JMP task-switch NT policy; multiword limit/wrap/restart boundaries; competing TF/NMI/INTR/fault events.
  • LOADALL is functional, but stepping-specific encoding, hidden-cache and silicon evidence is incomplete.
  • No 80287 coprocessor is included.
  • Instruction estimates, EU/IU/BIU overlap, prefetch refill, native Ts/Tc/READY phases and board wait/HOLD timing are not certified; aggregate 6/12 MHz reference results do not establish cycle or pin accuracy.
  • The F12 pause holds the CPU through HOLD/HLDA; it does not stop the CPU clock.
!
Current-source validation

The latest CPU and timing increments have directed checks, but their complete current-source regression and a new source-bound ZXTRES+ candidate acceptance are still outstanding. An older second MR BIOS restart fixture timed out with its cause unclassified; working MR BIOS reboots on hardware remain accepted observations. Four Landmark workloads lacked their exact ROM inputs. Five nonblocking physical CPU evidence notes are retained, one of them (an incomplete external capture) staying NOT EVALUABLE rather than counting as a pass.

Using the repository

Build, configuration and layout

The project builds with Vivado 2025.2 for the ZXTRES+'s xc7a100tfgg484-2. Builds use only this checkout, including the vendored CPU and its generated microcode; the DeMiSTify and mist-modules submodules must be checked out. 

# from the repository root; result: build/zxtres-pcat/vivado-pcat/PCAT286.ZX3
zxtres/scripts/build_firmware.sh   # EightThirtyTwo toolchain and controller firmware
zxtres/scripts/build_pcat.sh       # Vivado, to a .ZX3 file

Configuration

  • build_pcat.sh defines Sound Blaster, OPL2, C/MS and Tandy audio and the graphical boot splash; the .ZX3 file is loaded from the microSD card with the NMI browser of the ZX Spectrum core.
  • rtl/pcat286_zxtres_guest.sv is generated from PCAT-286.sv by scripts/make_guest.py; the board constraints are in zxtres/constraints.
  • Required-ROM detection and the preboot video raster stay active without the splash artwork.

The vendored CPU

  • vendor/spk286/ holds the pinned CPU RTL, the authoritative microcode, its generators and the CPU tests.
  • The microcode format uses 8-bit micro-operations, 10-bit addresses and 743 defined words in a synchronous block RAM ROM.
  • PCAT owns the whole rtl/timed/ overlay; a root generator checks it, and a sync tool imports upstream CPU changes while keeping the local timing overlay.
