DeMiSTify changes

PCAT-286 runs on the stock DeMiSTify controller (an EightThirtyTwo soft CPU that speaks the MiST SPI protocol), but it changes a good part of it: a coloured character-grid on-screen display, a longer menu, more disk units, a larger firmware ROM, keyboard handling and a configuration file. This page lists every change, where it lives, and which parts another ZXTres project can take as is. Nothing here is specific to the 80286: the PCAT-specific part is only the list of options in the core's CONF_STR and the image names in overrides.c.

How the changes are applied

DeMiSTify is not forked. It is a submodule, and zxtres/scripts/build_firmware.sh builds the firmware in a staging directory under build/zxtres-pcat/:

  1. copies config.h, overrides.c, osd.c, font.c and overrides.mk from zxtres/firmware/ over the upstream ones;
  2. patches diskimg.c with sed (unit mask, see disks);
  3. runs zxtres/scripts/expand_demistify_osd.py, which rewrites upstream main.c, menu.c and osd.h by exact string replacement. Every replacement asserts that it matches once, so a different upstream revision fails loudly instead of building a subtly different menu;
  4. builds with the EightThirtyTwo toolchain and writes controller_rom1_word.vhd, controller_rom2_word.vhd and controller.map.

The patched upstream files are never committed: the repository holds only the replacement files and the patch script, which makes updating DeMiSTify a matter of re-running the build and fixing the replacements that no longer match.

The OSD protocol

The stock MiST OSD receives a 1-bit pixel buffer on SPI channel SS3. That needs a large register array in the FPGA (Vivado built it from about 17 thousand registers) and the resulting text is small. This version keeps the same SPI channel and the same enable/disable commands but sends characters; the core owns the font and the palette.

CommandMeaning
0x20 | rowWrite menu row 0-15. Payload: attribute byte (bit 0 inverse = selected row, bit 1 stipple = greyed), then one character code per column, then one colour byte per column. A row that stops short keeps the colours it had.
0x30Write the info row, between title and menu (same payload).
0x31Write the help row, below the menu.
0x40 / 0x41Disable / enable the OSD.
0x50 | nBox position: 0 centre, 1 top-left, 2 top-right, 3 bottom-left, 4 bottom-right.

In firmware this is OsdWriteStart(row, inverse, stipple), OsdPutChar(c), OsdWriteEnd() and OsdSetPosition(pos) (osd.c). The grid is 32 columns by 16 menu rows plus the two extra rows. Glyphs are 8 lines high and 6 dots wide (8 on pictures under 300 lines, such as 15 kHz); at 31 kHz each line is doubled so the menu keeps the same on-screen height. The panel is the picture at an eighth of its brightness with a blue tint, the selected row is a blue bar with white text, and the box casts a shadow to the right and below.

Colours and icons

Inside any string, a byte of 1-8 selects the colour of what follows and takes no column. The palette lives in zxtres_osd.sv (6 bits per channel, scaled to the output depth):

The firmware names them C_CYAN to C_WHITE; code 8 maps to palette index 0, the other codes to themselves (3 bits per column are sent).

Codes 0x20-0x7F are ASCII. Codes 0x80-0x92 are menu symbols drawn for this OSD:

The font is built by zxtres/scripts/make_mem.py osdfont from the ASCII glyphs of font0.hex plus the symbol bitmaps.

Changing the theme

  • Palette: edit the case (color3) table in zxtres_osd.sv. No firmware change is needed, since the firmware only sends indices.
  • Panel, bar, frame, shadow: the block that follows the palette (bg_r/g/b, shadow3, frame3, the bar colour) in the same file.
  • Which rows get which colour: the draw_* functions and Menu_DrawRow in overrides.c (options, triggers, pages, images, rules, footer) and the text of the info and help lines in Menu_DrawExtras.
  • Per-item colours: put \001-\010 inside the CONF_STR label or in firmware strings.
  • Glyphs: change the symbol bitmaps in make_mem.py and regenerate osd_font.mem.
  • Size and grid: OSD_ROWS/OSD_COLS in the RTL and OSDNLINE and OSDLINELEN in the patched osd.h must agree.

The core can also pick the box position at run time: the firmware stores it in status bits 11-13 (OPT_POSITION) and sends 0x50 | pos every time the menu is drawn.

Menu behaviour

All implemented by expand_demistify_osd.py and the hooks in overrides.c (Menu_DrawRow, Menu_DrawExtras, Menu_AdjustRow):

  • 16 menu rows (upstream has 8) with an info line and a help line; the help line changes with the row kind (option, trigger, page, file selector).
  • L,Title; entries in CONF_STR draw a separator row with a title, and the cursor skips empty rows (Menu_NextRow).
  • Left/Right change the option under the cursor (Menu_AdjustRow); Enter cycles forward.
  • Esc backs out of a page, then closes the OSD (osd_escape()).
  • Key auto-repeat: 400 ms before the first repeat, then every 80 ms (KEY_REPEATFIRST, KEY_REPEATRATE).
  • The name of the mounted image follows a file-selector label (weak imagename() hook).
  • Pages: Confirm (27) before saving settings or loading defaults, Info (26), and Video info (25), which refreshes itself while shown from the signals zxtres_vidinfo.sv measures. The numbers are in the patch script, next to MENUPAGE_*.
  • CONFIG_AUTOCLOSE_OSD closes the menu after an image is loaded.

Keyboard

  • Win+F12 opens the OSD. Plain F12 stays available to the core, as MiSTer's F12KEYMOD does. zxtres_ps2_key.sv drops an F12 pressed with a Windows key (and its release) so the core never sees it.
  • While the OSD is open the keyboard is hidden from the core (osd_open); when it closes the Windows keys count as up.
  • The module converts PS/2 set 2 bytes into MiSTer-style ps2_key events (bit 10 toggles per event, bit 9 make/break, bit 8 E0 prefix, bits 7:0 code) and swallows the Pause E1 sequence and keyboard replies (BAT, ACK, echo, resend).

Disk images, file selector, CFG file

  • Units: CONFIG_DISKIMG_UNITS 5, and the sed patch raises the diskimg.c unit mask from 0x03 to 0x07 (two hard disks, the CMOS file, two floppies; adapt the count to your core).
  • File lines: fileline() draws icon, NAME.EXT and size in the right columns; names are 8.3 (FAT without LFN), so the selector rows hold 40 characters (romfilenames[OSDNLINE-1][40]).
  • Settings file: PCAT286.CFG is a fixed 512-byte file (version 3) with status bits and 80-byte image paths, folders counted from the root. DeMiSTify's firmware cannot create files, so the file must already exist on the card (see zxtres/README.md for how it is made).
  • Autoboot: autoboot() loads the ROM images from a named folder when the core starts.
  • CONFIG_FILEBOOKMARKS 16 is enabled in config.h (DeMiSTify's folder bookmarks for the file selector).

If your build fails with the ROM full, raise the three package constants together and check controller.map.

Reusing it in another core

  1. Copy zxtres/firmware/{osd.c,font.c,overrides.mk}, zxtres/scripts/{expand_demistify_osd.py,build_firmware.sh,make_mem.py} and zxtres/rtl/zxtres_osd.sv.
  2. In your top level instantiate zxtres_osd between the core's video and the VGA output, with the controller's SS3 SPI lines and FONT_FILE pointing to the generated font memory (make_mem.py osdfont). Check zxtres_pcat_top.sv for the connections used here.
  3. Start from overrides.c: keep the "look of the menu" section (colour/icon defines, draw_*, Menu_DrawRow, Menu_AdjustRow, Menu_DrawExtras, fileline) and replace the PCAT-specific parts: image names and slots, OPT_CPU, OPT_RAM, OPT_MONITOR (the options shown on the info line), CFG layout and autoboot(). If you do not want the info line, change Menu_DrawExtras.
  4. Set your own CONF_STR using L,Title; separators and colour codes, and your own option numbers.
  5. Adjust config.h and the ROM-size package to your feature set, then build firmware before the bitstream.
  6. Pick a theme (above): only zxtres_osd.sv and the font change for a pure re-skin.
